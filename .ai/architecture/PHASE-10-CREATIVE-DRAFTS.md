# TASK-0059 portable creative draft boundary

Explicit immutable `creative_text` and `creative_image` policies are registered before implementation. Each pins output schema, disclosure, rights/provenance requirements, safety/brand/rights review kinds and conservative offline text/media bounds. Unsupported capability, mutable version or changed bytes deny. Only registered offline policy hashes and `AiCreativeProvider` fixture implementations can use this path; a route labeled live is rejected before invocation. No actual provider account, credential, paid model request or SDK is configured.

`AiCreativeDraftGenerator` uses authenticated workspace/brand scope, the existing permission-checking context assembler, a required brand guideline and independently verified scoped input rights/policy bound to exact request hashes. Model approval flags cannot provide that authority. It composes the existing gateway for privacy/region/capability/schema filtering, bounded fallback, cost reservation/accounting, circuit and reference-only telemetry.

Outputs are bounded text and zero/one PNG or JPEG payload. Extra fields, arbitrary asset URLs, foreign or invented references, unsafe text, refusal/incomplete/cancellation, missing provider-request provenance and unsupported media deny or withhold output. Fileinfo inspects MIME and the parser checks bounded dimensions/header metadata; this is not complete image decoding, malware screening or a commercial-rights certificate. Parser errors become generic denial without logging binary bytes. Media stays a base64 review payload, with exact byte hash and size; this path writes no object store, canonical asset, content document, publication or external account. Future downstream use must pass the existing canonical ingestion and tool policy paths.

The server attaches `AI-generated draft; independent review required.`, immutable policy/context hashes, input rights reference, provider request reference, creator/scope and candidate fingerprint. `content_credentials` explicitly remains `unverified`: a hash/reference is not C2PA verification. Rights are verified by trusted policy services, never asserted from model prose or inferred from C2PA metadata.

`AiCreativeReviewGate` requires `ai.approve`, exact workspace/brand/candidate fingerprint and current independently verified human rights, brand and safety reviews. The creator and specialist agents cannot self-review. Changed candidate bytes invalidate prior reviews. Its outcome is a reviewed draft with `publication_authorized: false`; publication/send/ingestion remain separate authorized operations. No permissive authority binding or new UI/API endpoint is installed.

Invalid-output verification also repaired an existing gateway truth gap: telemetry/circuit success was finalized before output validation. Final durable status now reflects `validation_failed`, known usage is still accounted, and repeated invalid output trips the configured circuit. A DB-backed regression checks three rejected traces, cost accounting, withheld output and the stopped fourth invocation without retaining private output.

No dependency or migration is introduced. Numeric file/dimension bounds describe the offline contract, not production capacity or provider limits. Fixtures prove portable policy behavior, not live creative quality, safety classifier accuracy, model latency/cost, account privacy controls, verified C2PA or publication readiness. Locked full application/security/continuity/PostgreSQL/PHP-floor/E2E gates remain required.
