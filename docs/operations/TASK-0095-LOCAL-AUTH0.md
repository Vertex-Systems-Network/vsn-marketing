# TASK-0095 local Auth0 exercise

This is a development-only runbook. The live exercise requires a browser and the VSN Docker Compose runtime on the same operator machine. Keep the Auth0 client secret in the untracked `.env` file; never paste it into a PR, screenshot or support chat.

1. From the repository root, copy `.env.example` to `.env`. Keep `APP_ENV=local`, `APP_URL=http://127.0.0.1:8000`, `SESSION_SECURE_COOKIE=false`, and `ENTERPRISE_OIDC_ENABLED=false` while preparing the environment.
2. Start the local services with `docker compose up --build -d`. Generate an application key using `docker compose exec app php artisan key:generate`, then apply forward migrations with `docker compose exec app php artisan migrate --force`. Visit `http://127.0.0.1:8000` and check `docker compose ps` if it is unavailable. Do not run a database reset on an existing workspace.
3. Use an isolated test workspace with a known UUID, an existing VSN member and two separately authenticated workspace identity administrators. In Auth0, use the Development tenant's Regular Web Application and a verified test user. Confirm the user's exact Auth0 `sub` through the trusted tenant dashboard; never infer the VSN member from email.
4. In that Auth0 application's Settings, add the exact `http://127.0.0.1:8000/auth/enterprise/<WORKSPACE_UUID>/callback` to **Allowed Callback URLs** and save it. Set `.env` `ENTERPRISE_OIDC_WORKSPACE_ID` to the UUID and `ENTERPRISE_OIDC_REDIRECT_URI` to the same absolute URL. Set `ENTERPRISE_OIDC_ISSUER` to the exact tenant HTTPS origin with trailing slash; set the client ID and client secret from the same application. Pin the tenant's current RS256 signing key ID and base64-encoded PEM public key in `ENTERPRISE_OIDC_KEY_ID` and `ENTERPRISE_OIDC_PUBLIC_KEY_PEM_BASE64` respectively. Keep the private signing key at Auth0. Key rotation requires updating the pinned pair before testing again.
5. Set `ENTERPRISE_OIDC_LOCAL_HTTP_CALLBACK=true` and reload the app configuration (`docker compose exec app php artisan config:clear`). The binding workflow uses authenticated `identity.manage` POST requests under `/workspaces/<WORKSPACE_UUID>/identity/federation-bindings`: propose `{ "user_id": "<VSN_USER_UUID>", "subject": "<EXACT_AUTH0_SUB>" }`; a second administrator POSTs `/<PROPOSAL_UUID>/approve`; the proposer POSTs `/<PROPOSAL_UUID>/apply`. Use the app's normal browser session and CSRF token for all three actions. Verify the pairing with both administrators before approval.
6. Set `ENTERPRISE_OIDC_ENABLED=true`, clear config again, and open `http://127.0.0.1:8000/auth/enterprise/<WORKSPACE_UUID>/login` in a new browser session. Verify redirect to the configured Auth0 tenant, successful return to `/workspaces`, one-use callback rejection on refresh, and failed login for an unbound or deactivated member. Record redacted test evidence and exact source commit; do not capture tokens, secrets or user PII.
7. Set `ENTERPRISE_OIDC_ENABLED=false` and `ENTERPRISE_OIDC_LOCAL_HTTP_CALLBACK=false` after the exercise. This local result alone does not certify the full SCIM, governance, or Phase 16 acceptance criteria.

The HTTP exception is gated in code to `APP_ENV=local`, explicit opt-in, and an exact loopback route. Production and other environments continue to require HTTPS.
